# 在規劃對話設定專案 Git 流程

設定以專案為單位，第一次規劃時整理一次；後續任務沿用已確認版本，不必每張卡重填。
代理先讀該專案的文件與規則，再透過 `get_project_workflow` 讀取目前設定、透過
`prepare_project_workflow` 保存草稿。看板網頁只顯示內容與狀態，不直接修改設定。

## 從規劃到套用

1. 在規劃對話明示專案名稱。代理整理起始分支、整合目標、PR／MR 規則、必要檢查、
   審查規則、合併權限及 DONE 時機，附上文件來源與版本。
2. 代理只詢問文件無法決定的選項。缺少欄位或有待決問題時，草稿不可核准；不得用猜測補值。
   `SUGGESTION` 保留原始提案的來源；人類完整核准後即表示採用，不必先把來源改寫成已確認規則。
3. 代理保存草稿，說明差異與影響。既有已確認設定繼續有效，草稿不會立即改變任務的規則。
4. 人類在自己的終端機執行下列固定核准工具。工具直接從看板讀取草稿，顯示七個欄位、來源、
   草稿／基底版本、缺欄、問題與差異；閱讀後輸入完整確認文字才會簽署。
5. 核准前工具再次讀取草稿；版本或指紋變動即停止，要求重新閱讀。後端也檢查版本，
   因此兩次讀取之後再發生的競態仍會被拒絕。核准成功後，工具重新讀取並確認生效版本。

核准工具不讀代理提供的檔案、不接受任意執行指令、不執行 Git，也沒有 `--yes`。
確認設定不構成 commit、push、建立 PR／MR、合併、部署或發布的授權。

## owner 環境的一次性配置

需要 Node.js 22。由管理者在獨立的 owner 操作環境配置憑證，不能把簽署金鑰交給開發代理、
受測程式或測試執行器。此工具與核准金鑰若和任意代理共享可讀的帳號／檔案系統，
`0600` 與互動提示不能提供對該代理的安全隔離；應使用不同的作業系統帳號或受控工作站。

JSON 檔放在 repo 外，由操作者擁有，權限必須為 `0600`，不得使用 symlink：

```json
{
  "mcpUrl": "http://127.0.0.1:8081/mcp",
  "actor": "project-owner",
  "secret": "由管理者安全配置的至少32字元獨立金鑰"
}
```

上述為格式範例，不能把範例字串當正式金鑰。`actor` 必須由看板管理者預先設定為
對該專案具有 `PROJECT_POLICY` 核准權的身分，`secret` 必須與該設定一致。
Java 的既有簽署者配置見 [驗收協定](acceptance-protocol.md)。本次功能沒有替正式環境配置金鑰。

Workers 另外需要 `machineToken` 字串作為 Bearer 機器憑證；該機器不需要管理角色，
但仍須通過 Workers 本身的裝置驗證。Java 本機可省略 `machineToken`。
不需要把 leader 管理憑證放進此檔。
只接受 HTTPS，或 `localhost`、`127.0.0.1`、`::1` 的 HTTP；路徑固定 `/mcp`，
拒絕重新導向、URL 帳密、query 與 fragment。

人類在 owner 環境自己的互動終端機執行：

```bash
node bin/approve-project-workflow.mjs --project '範例專案' --credentials /owner-only/board-owner.json
```

依畫面顯示的草稿版本完整輸入，例如 `確認 範例專案 #3`。其他輸入會取消，
管線、無終端機執行及自動同意參數都不接受。工具不輸出金鑰、Bearer、簽署 payload 或 signature，
只在記憶體中簽署固定核准事件；伺服器保存核准者與 `owner-cli:時間:唯一識別碼` 的核准紀錄。
若送出後連線中斷，先重新讀取看板設定確認結果，不要直接重送。

## 版本與適用範圍

已確認設定包含確認者與核准紀錄；未設定的專案不得自行猜分支或自動整合。
規則變更時建立新草稿並重新核准，後續驗收契約必須使用符合目前規則的設定。
`ACCEPTED` 表示獨立驗收完成可 DONE；`INTEGRATED` 另需符合整合條件才 DONE。
DONE 解鎖相依，但不代表已發布。公司實際 Git 流程仍由公司負責人決定。

## 局部驗證

```bash
node --test scripts/project-workflow-check/approval-helper.test.mjs
```

測試涵蓋固定草稿簽署、拒絕／無 TTY、確認期間修改、摘要錯配與缺欄、URL 限制、
檔案權限，以及有 session 和 Bearer 的真 HTTP MCP fixture。這是核准工具的協定與
安全測試，並不表示正式環境的金鑰、公司規則或公司系統已驗收。
